Étape 3 : Créer le modèle Artist
Vous pouvez passer cette étape si vous avez déjà réalisé le kit de démarrage.
Si ce n’est déjà fait, créez un modèle pour les artistes.
reservations\catalogue\models\artist.py
from django.db import models
from .type import *

class Artist(models.Model):
    firstname = models.CharField(max_length=60)
    lastname = models.CharField(max_length=60)

    def __str__(self):
        return self.firstname +" "+ self.lastname
    
    class Meta:
        db_table = "artists"

Notez qu’il s’agit ici d’un minimum. Votre modèle Artist peut contenir plus de définitions que le présent code source, si vous aviez déjà avancé dans les autres roadmaps.

Étape 7 : Tester l’API
Démarrez le serveur de développement :
python manage.py runserver
Dans votre navigateur, vous pouvez directement tester les endpoints en requête GET en accédant aux URLs suivantes :
* http://localhost:8000/catalogue/api/artists/ 
* http://localhost:8000/catalogue/api/artists/1/  


Par contre, pour tester les requêtes POST, PUT et DELETE, il faut utiliser un client Rest tel que Postman ou cURL.
Utilisation de cURL
Pour utiliser cURL, vous devez ouvrir un terminal de commande Git Bash. Attention, n’oubliez pas de mentionner le slash final pour chaque terminaison d’URL (endpoint).
* Récupérer tous les artistes
curl -i -H "Accept: application/json" -H "Content-Type: application/json" -X GET http://localhost:8000/catalogue/api/artists/
* Récupérer un artiste spécifique
curl -i -H "Accept: application/json" -H "Content-Type: application/json" -X GET http://localhost:8000/catalogue/api/artists/1/
* Ajouter un artiste
curl -X POST -H "Content-Type: application/json" -d '{"firstname": "Bob", "lastname": "Sull"}' http://localhost:8000/catalogue/api/artists/
* Modifier un artiste spécifique
curl -X PUT -H "Content-Type: application/json" -d '{"firstname": "Fred", "lastname": "Astaire"}' http://localhost:8000/catalogue/api/artists/1/
* Supprimer un artiste spécifique
curl -X DELETE http://localhost:8000/catalogue/api/artists/1/
Attention, il est possible que vous obteniez une erreur de type RestrictedError “Exception value : Cannot delete some instances of Model Artist because they are referenced through restricted foreign keys…”. En effet, si l’artiste que vous voulez supprimer a une relation avec le modèle Type par exemple, vous ne pourrez pas le supprimer sans supprimer en premier la relation. Pour tester la suppression, créez d’abord un nouvel artiste. Retrouver l’id qui lui a été attribué et vous pourrez ensuite le supprimer en renseignant son id. Par exemple, si son id est 14  :
curl -X DELETE http://localhost:8000/catalogue/api/artists/14/
Utilisation d’un client Rest graphique
Vous pouvez pour plus de comfort installer un client Rest avec une interface graphique. Postman est assez répandu dans la profession. Toutefois, nous ne la recommandons plus en formation car elle nécessite désormais de s’inscrire sur leur site même pour la version gratuite.
En guise d’alternative, si vous  développez sur VSCode, vous pouvez utiliser l’extension Thunder Client1. L’EDI IntelliJ propose par défaut son extension HTTP Client2. Vous n’aurez donc rien à installer de plus. Par contre, sur Eclipse, nous n’avons pas trouvé de solution satisfaisante dans le market place à ce jour. C’est pourquoi, dans la suite de ce roadmap, nous utiliserons une extension Chrome. Vous pouvez donc installer l’extension Talend API Tester3 dont la version gratuite est amplement suffisante. 




Étape 8 : Authentification
Pour ajouter une authentification aux requêtes POST, PUT, et DELETE dans une API Django REST Framework (DRF), vous pouvez configurer l'authentification et les permissions. Voici comment procéder :

Étape 8.1 : Ajouter des permissions globales

Étape 8.2 : Ajouter des permissions spécifiques aux vues
Si vous souhaitez appliquer des permissions uniquement aux requêtes POST, PUT, et DELETE, vous pouvez utiliser la classe DjangoModelPermissions ou une permission personnalisée.
Exemple d’utilisation de DjangoModelPermissions dans les vues :
reservations\api\catalogue\views.py
from rest_framework.permissions import DjangoModelPermissions
from rest_framework import generics
from catalogue.models import Artist
from .serializers import ArtistSerializer

class ArtistListCreateView(generics.ListCreateAPIView):
    queryset = Artist.objects.all()
    serializer_class = ArtistSerializer
    permission_classes = [DjangoModelPermissions]

class ArtistRetrieveUpdateDestroyView(generics.RetrieveUpdateDestroyAPIView):
    queryset = Artist.objects.all()
    serializer_class = ArtistSerializer
    permission_classes = [DjangoModelPermissions]
    
DjangoModelPermissions :
* Autorise les actions basées sur les permissions définies dans Django (e.g., add_artist, change_artist, delete_artist).
* Vous devez associer ces permissions aux utilisateurs ou groupes via l’interface d’administration Django.
Connectons-nous au back-office de Django http://localhost:8000/admin. Si ce n’est déjà fait, créez un utilisateur qui fera partie du groupe MEMBER. Retirez-lui toutes les permissions sauf les permissions View. Vous pouvez définir les permissions par groupe ou pour un utilisateur en particulier.

Étape 8.3 : Ajouter des permissions personnalisées (optionnel)
Si vous avez besoin de permissions plus granulaires (e.g., seulement restreindre POST, PUT, et DELETE), créez une classe de permission personnalisée.
reservations\api\catalogue\permissions.py
from rest_framework.permissions import BasePermission, SAFE_METHODS

class IsAuthenticatedOrReadOnly(BasePermission):
    """
    Autorise les requêtes de lecture pour tout le monde,
    mais exige l'authentification pour POST, PUT et DELETE.
    """

    def has_permission(self, request, view):
        # Autorise toutes les requêtes de lecture (GET, HEAD, OPTIONS)
        if request.method in SAFE_METHODS:
            return True
        # Autorise POST, PUT, DELETE uniquement pour les utilisateurs authentifiés
        return request.user and request.user.is_authenticated

Appliquez cette permission aux vues concernées.
reservations\api\catalogue\views.py

Étape 8.4 : Ajouter une authentification via Token (optionnel)
L’authentification par token fournie par Django REST framework est une implémentation relativement simple. Nous n’allons donc pas l’utiliser mais installer un autre paquetage.
« JSON Web Token est une norme relativement nouvelle qui peut être utilisée pour l'authentification basée sur des jetons. Contrairement au schéma TokenAuthentication intégré, JWT Authentication n'a pas besoin d'utiliser une base de données pour valider un jeton. Un package pour l'authentification JWT est djangorestframework-simplejwt qui fournit certaines fonctionnalités ainsi qu'une application de liste noire de jetons enfichable. »4
Si vous souhaitez utiliser des tokens pour l’authentification, ajoutez la dépendance suivante :
pip install djangorestframework-simplejwt
Configurez settings.py pour inclure JWT :
reservations\reservations\settings.py
#...

# REST Framework authentications & parmissions
# https://www.django-rest-framework.org/api-guide/authentication/

    'DEFAULT_AUTHENTICATION_CLASSES': [
        # Pour l'authentification basée sur la session
        'rest_framework.authentication.SessionAuthentication',
        # Pour l'authentification de base (utile pour Postman/cURL)
        'rest_framework.authentication.BasicAuthentication',

Différence entre RPC et API Restful
En fait, ce que nous avons construit jusqu'à présent est mieux décrit comme RPC (Remote Procedure Call), car il n'y a aucun moyen de savoir comment interagir avec ce service. Si vous publiiez cela aujourd'hui, vous devriez également rédiger un document ou héberger un portail de développeurs quelque part avec tous les détails.
Pour rendre cette solution conforme aux principes RESTful hypermedia (HATEOAS - Hypermedia as the Engine of Application State), vous devez inclure des liens hypermédia dans les réponses de l'API. Ces liens aident les clients à naviguer dans les ressources sans avoir besoin de connaître la structure exacte des endpoints à l'avance.
Structure des réponses avec hypermedia
Chaque réponse doit inclure des liens qui décrivent les actions possibles sur la ressource. Par exemple, une réponse pour un artiste pourrait inclure des liens pour :
* Afficher les détails de l'artiste.
* Modifier l'artiste.
* Supprimer l'artiste.
Extrait de la documentation5 :
REST Framework est une boîte à outils API Web agnostique. Il vous aide à créer des API bien connectées et facilite la conception de types de médias appropriés, mais il n'impose pas strictement un style de conception particulier.
REST Framework permet de créer des API hypermédias. L'API navigable qu'il propose est basée sur HTML - le langage hypermédia du Web.
Il comprend également des composants de sérialisation et d'analyse/rendu qui facilitent la création de types de médias appropriés, des relations hyperliées pour la création de systèmes bien connectés et un excellent support pour la négociation de contenu.
Ce que REST Framework ne fait pas, c'est vous fournir des formats hypermédias lisibles par machine tels que HAL, Collection+JSON, JSON API ou des microformats HTML par défaut, ou la possibilité de créer automatiquement des API de style HATEOAS complet qui incluent des descriptions de formulaire basées sur l'hypermédia et des hyperliens étiquetés sémantiquement. Cela impliquerait de faire des choix avisés sur la conception des API qui devraient vraiment rester en dehors du champ d'application du framework.

Étape 9 : Ajouter HATEOAS avec un hyperlinked serializer
Pour respecter le principe HATEOAS, utilisez un HyperlinkedModelSerializer.
reservations\catalogue\models\serializers.py
from rest_framework import serializers
from catalogue.models import Artist
from rest_framework.reverse import reverse

class ArtistSerializer(serializers.HyperlinkedModelSerializer):
    links = serializers.SerializerMethodField()

    class Meta:
        model = Artist
        fields = ['id', 'firstname', 'lastname', 'links']

    def get_links(self, obj):
        request = self.context.get('request')
        return {
            'self': reverse('catalogue:artist-detail', kwargs={'pk': obj.id}, request=request),
            'all_artists': reverse('catalogue:artist-list', request=request),
        }

from rest_framework.test import APITestCase
from rest_framework import status
from catalogue.models import Artist

class ArtistAPITests(APITestCase):
    def test_create_artist(self):
        data = {'firstname': 'John', 'lastname': 'Doe'}
        response = self.client.post('/catalogue/api/artists/', data)
        self.assertEqual(response.status_code, status.HTTP_201_CREATED)

    def test_get_artist_list(self):
        Artist.objects.create(firstname='Jane', lastname='Smith')
        response = self.client.get('/catalogue/api/artists/')
        self.assertEqual(response.status_code, status.HTTP_200_OK)
